## To Use
1. Ensure you're on a feature branch / worktree.
2. Copy the Ralph into your project:
    ```bash
    mkdir -p .ralph && cp ~/RALPH/ralph.sh .ralph/
    ```
3. Initialize project:
    - Run the `/prd` skill to generate `.ralph/PRD.md`, `.ralph/TRACK.md`, `.ralph/progress.txt`, and `.ralph/prompt.md`
4. Run `./.ralph/ralph.sh`

Optional: Before merging, remove Ralph run files if you do not want them in the final PR diff:
- `git rm -r .ralph`

## Ralph HITL (Human-In-The-Loop)

Same as Ralph, but you run one task at a time and stay in control:

```bash
mkdir -p .ralph && cp ~/RALPH/ralph-hitl/hitl.sh .ralph/
```

Then:
```bash
./.ralph/hitl.sh        # Run one task
./.ralph/hitl.sh        # Run the next task
# ... repeat as needed
```

**Use HITL when:**
- Testing a new feature track for the first time
- Debugging mid-feature or catching failures early
- You want to stay engaged and build intuition

**Use Ralph when:**
- You have a stable, well-tested track
- You're confident in the breakdown
- You're comfortable going AFK

See [ralph-hitl/README.md](ralph-hitl/README.md) for details.

## File Structure

```
my-project/
  ├── src/
  │   └── ... (main codebase)
  │
  └── .ralph/
      ├── ralph.sh              # The bash loop runner
      ├── prompt.md             # Agent instructions
      ├── PRD.md                # Feature overview and goals
      ├── TRACK.md              # Implementation tasks and state
      └── progress.txt          # Iteration log and learnings
```

## Key Files

| File | Purpose | Source |
|------|---------|--------|
| `ralph.sh` | Bash loop that spawns Claude for each iteration | You provide |
| `prompt.md` | Agent instructions: boundaries, steps, completion criteria | You provide |
| `prd.md` | Template/guide for breaking features into tasks | You provide |
| `PRD.md` | Feature overview, goals, scope | Generated by `/prd` |
| `TRACK.md` | Tasks with acceptance criteria and completion state | Generated by `/prd` |
| `progress.txt` | Iteration log and learnings for future runs | Generated by `/prd` |

Task completion is tracked by markdown checkboxes in `TRACK.md`: `### [ ] T-001: Task title` becomes `### [x] T-001: Task title`.
